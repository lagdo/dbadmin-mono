Using a secret manager in the dev env
=====================================

By default Jaxon DbAdmin will load the database connection options and credentials from its config file, or from the `.env` and `.env.dbadmin` files.
In the dev env, they are located in the `dbadmin-demo/` dir, and not included in this repo.

The `docker/compose-secrets` provides containers that run the supported secret managers, or equivalent emulators, for testing.
  - `infisical`: [Infisical](https://infisical.com/)
  - `ministack`: [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/)
  - `gcp-secret-manager`: [GCP Secret Manager](https://cloud.google.com/security/products/secret-manager)
  - `openbao`: [OpenBao](https://openbao.org) (compatible with [HashiCorp Vault](https://www.hashicorp.com/fr/products/vault))

There is also an instance of the Nginx web server running in the `secrets-nginx` container whichs provides secure access with a local root certificate.
The root and server certificates are generated by a script in the `secrets-certs` container, using the `mkcert` command, and stored in the `docker/ssl` dir. The file names are `dbadmin_root_ca.pem`, `secrets.loc.crt` and `secrets.loc.key`.

>Note: See https://blog.stephane-robert.info/post/homelab-certificats-https-ssl-mkcert/ for more information.

The `secrets-nginx` depends on the `secrets-certs` container, and makes sure it has exited successfully before starting.

The `docker/compose-dbadmin` dir has an additional `docker-compose.secrets.yml` file which enables the connection to a secret server to read database credentials.
So the first step is to build `docker/compose-secrets` containers, then the `docker/compose-dbadmin` containers with:

```bash
docker compose -f docker-compose.yml -f docker-compose.secrets.yml up -d
```

The `dbadmin-dev` and `dbadmin-cli` Dockerfile's will install additional libraries and CLI tools to setup the secret servers.
They will also install the above `dbadmin_root_ca.pem` root certificate, so the client libraries and commands can connect to the secret servers using HTTPS connections.

When the database credentials are fetched from a secret servers, the `username` and `password` options can be removed from the config options.
In the `dbadmin-demo/app/config/servers.php` and `dbadmin-demo/.env.dbadmin` files for example, the `dbadmin-pgsql-14` server entry will be changed to this.

```php
// dbadmin-demo/app/config/servers.

            'dbadmin-pgsql-14' => [
                'driver' => 'pgsql',
                'name' => 'PostgreSQL 14',
                'host' => env('PGSQL14_DB_HOST'),
                'port' => env('PGSQL14_DB_PORT'),
                // The credentials are removed
                // 'username' => env('PGSQL14_DB_USERNAME'),
                // 'password' => env('PGSQL14_DB_PASSWORD'),
            ],
```

```bash
# dbadmin-demo/.env.dbadmin

PGSQL14_DB_HOST=pgsql.addr
PGSQL14_DB_PORT=5433
# The credentials are removed
# PGSQL14_DB_USERNAME=postgres
# PGSQL14_DB_PASSWORD=dbadmin
```

### Accessing the secure domains from the desktop

In order to avoid warnings about unverified certificates, the above `dbadmin_root_ca.pem` root certificate must be installed in the browser on the desktop.
The procedure depends on the browser.

Then add the following line in the network `hosts` file.

```
127.0.0.1 inf.secrets.loc aws.secrets.loc gcp.secrets.loc bao.secrets.loc
```

### Infisical

Configuring the secrets in the [Infisical](https://infisical.com/) server requires to access its backend from a browser.

Make sure the `infisical-backend` container in the `secrets` project in Docker is up and running.
Then browse the `https://inf.secrets.loc:7201` URL, create an account.

Following [this tutorial](https://medium.com/@thierry.feuzeu/secure-the-jaxon-dbadmin-database-credentials-with-infisical-995979891bad), create a project of type Secrets Management, a machine identity, and a secret in the `Universal Auth` for Jaxon DbAdmin.
Make sure to copy the `project id`, as well as the auth `client id` and `client secret id`. 

Enter the CLI console in the `dbadmin-cli` container in the `dbadmin-dev` project in Docker, and run the `infisical login -i` command, enter `https://inf.secrets.loc` as the self-hosting domain, and provide the credentials of the account just created.

Run the following commands to create the secrets.

```bash
cd /home/dbadmin/secrets/infisical/
infisical login --method=universal-auth --client-id=<client-id> --client-secret=<client-secret>
infisical secrets --projectId=<project-id> --env dev
./create-secrets.sh
```

In the `dbadmin-demo/app/config/secrets.php` file, set the `reader` option.

```php
    'reader' => InfisicalConfigProvider::class,
```

In the `dbadmin-demo/.env` file, set the following options.

```bash
INFISICAL_SERVER_URL=https://inf.secrets.loc
INFISICAL_PROJECT_ID="<project-id>"
INFISICAL_MACHINE_CLIENT_ID="<client-id>"
INFISICAL_MACHINE_CLIENT_SECRET="<client-secret>"
INFISICAL_PROJECT_ENV=dev
```

### AWS Secrets Manager (Ministack)

Make sure the `ministack` container in the `secrets` project in Docker is up and running.
Then enter the CLI console in the `dbadmin-cli` container in the `dbadmin-dev` project in Docker, and run the following commands to create the secrets.

```bash
cd /home/dbadmin/secrets/aws/
./setup-client.sh
./create-secrets.sh
```

In the `dbadmin-demo/app/config/secrets.php` file, set the `reader` option.

```php
    'reader' => AwsSecretConfigProvider::class,
```

In the `dbadmin-demo/.env` file, set the following options.

```bash
AWS_SECRETS_SERVER_URL=https://aws.secrets.loc
AWS_SECRETS_REGION=us-east-1
AWS_SECRETS_VERSION=latest
# Authentify with a saved profile.
AWS_SECRETS_CLIENT_PROFILE=dbadmin
```

### GCP Secret Manager

Make sure the `gcp-secret-emulator` container in the `secrets` project in Docker is up and running.
Then enter the CLI console in the `dbadmin-cli` container in the `dbadmin-dev` project in Docker, and run the following commands to create the secrets.

```bash
cd /home/dbadmin/secrets/gcp/
./create-secrets.sh
```

The PHP client SDK requires an authentication file to connect to the service.
As documented in [this tutorial](https://dev.to/jajera/best-practice-set-up-gcloud-auth-and-application-default-credentials-adc-3dhk), run the following command.

```bash
gcloud auth application-default login
```

>Note: If the `gcloud` command is not available, then first run the `. /etc/profile.d/gcloud-sdk.sh` command.

Open the printed URL in a browser, follow the instructions, and enter the provided key.
Upon success, the credentials file will be saved in `/home/dbadmin/.config/gcloud/application_default_credentials.json`, and automatically made available in the `dbadmin-dev` container.

In the `dbadmin-demo/app/config/secrets.php` file, set the `reader` option.

```php
    'reader' => GcpSecretConfigProvider::class,
```

In the `dbadmin-demo/.env` file, set the following options.

```bash
GCP_SECRETS_SERVER_URL=gcp.secrets.loc # Must be an https endpoint.
GCP_SECRETS_PROJECT_ID=dbadmin
GCP_SECRETS_VERSION=latest
GOOGLE_APPLICATION_CREDENTIALS=/home/dbadmin/.gcp/application_default_credentials.json
```

### OpenBao

Configuring the secrets in the [OpenBao](https://openbao.org) server requires to access its backend from a browser.

Make sure the `openbao` container in the `secrets` project in Docker is up and running.
Then browse the `https://bao.secrets.loc:7201` URL, let the `Namespace` field empty, select `Token` in the `Method` dropdown, enter `dbadmin` in the `Token` field, and click the `Sign in` button.

In the `Secrets Engines` page, click the `Enable new engine` button, select `KV` as the engine type, and click `Next`.
Enter `dbadmin` in the `Path` field, and click the `Enable engine` button.

Enter the CLI console in the `dbadmin-cli` container in the `dbadmin-dev` project in Docker, and run the following commands to create the secrets.

```bash
cd /home/dbadmin/secrets/openbao/
./create-secrets.sh
```

In the `dbadmin-demo/app/config/secrets.php` file, set the `reader` option.

```php
    'reader' => OpenBaoConfigProvider::class,
```

In the `dbadmin-demo/.env` file, set the following options.

```bash
OPENBAO_AUTH_TOKEN=dbadmin
OPENBAO_PROJECT_ID=dbadmin
OPENBAO_SERVER_PATH=
OPENBAO_SERVER_URL=https://bao.secrets.loc
```
